# Linux Administration and Network Troubleshooting Labs

## Overview

This repository documents my hands-on practice in Linux system administration, network troubleshooting, service management, packet analysis, and fault recovery.

The labs are performed in a virtualized lab environment using VMware Workstation Pro and Ubuntu Linux. The purpose is to develop practical troubleshooting skills relevant to Network Engineer, System Administrator, IT Infrastructure Support, and Technical Support Engineer roles.

I document each lab with its objectives, environment, commands, test results, troubleshooting steps, evidence, and lessons learned.

## Lab Index

### Lab 01 — Linux Files, Users, and Permissions
**Topics:** File navigation, searching, ownership, permissions, groups, and privilege management.

Commands practiced:
- `pwd`, `ls`, `find`, `grep`
- `chmod`, `chown`
- `whoami`, `groups`, `sudo`

Objectives:
- Navigate the Linux filesystem.
- Search for files and text.
- Understand file ownership and permission modes.
- Explain the principle of least privilege.

### Lab 02 — Linux Services and System Monitoring
**Topics:** Service management, logs, processes, memory, and disk usage.

Commands practiced:
- `systemctl`, `journalctl`
- `ps`, `top`
- `df -h`, `free -h`

Objectives:
- Inspect service status.
- Review service logs.
- Identify processes consuming system resources.
- Diagnose basic service and resource issues.

### Lab 03 — Linux Network Troubleshooting
**Topics:** IP addressing, routing, DNS resolution, connectivity, and listening ports.

Commands practiced:
- `ip addr`, `ip route`
- `ping`, `traceroute`
- `dig`, `nslookup`, `getent`
- `curl`, `ss -tuln`

Objectives:
- Inspect network interfaces and routes.
- Test IP connectivity and DNS resolution.
- Identify listening sockets.
- Follow a structured troubleshooting methodology.

### Lab 04 — Wireshark DNS and TCP Analysis
**Topics:** Packet capture, DNS query/response, TCP handshake, and display filters.

Tools and filters:
- Wireshark
- `dns`
- `tcp`
- `tcp.flags.syn == 1`
- `tcp.flags.syn == 1 && tcp.flags.ack == 1`

Objectives:
- Capture traffic generated by my own lab.
- Identify DNS queries and responses where visible.
- Analyze TCP connection establishment.
- Document packet-level observations.

### Lab 05 — DNS Fault Diagnosis and Recovery
**Topics:** Baseline testing, controlled DNS misconfiguration, fault isolation, recovery, and validation.

Objectives:
- Record a known-good baseline.
- Introduce a controlled fault in an isolated test VM.
- Compare expected and observed behavior.
- Restore the original configuration.
- Verify recovery using repeatable tests.

### Lab 06 — Technical Documentation and Job Readiness
**Topics:** Troubleshooting reports, evidence collection, technical communication, and interview preparation.

Objectives:
- Produce clear technical documentation.
- Maintain a record of completed labs.
- Explain root cause and corrective actions.
- Map demonstrated skills to relevant job requirements.

## Troubleshooting Methodology

I use the following workflow when investigating technical issues:

1. Establish the baseline and confirm the reported symptoms.
2. Gather evidence using commands, logs, and packet captures.
3. Isolate the problem by testing one layer or component at a time.
4. Identify the most likely root cause from the available evidence.
5. Apply a controlled corrective action.
6. Repeat the original tests to verify the fix.
7. Document the result and any remaining limitations.
